# Independent confirmation asset screen

Updated 2026-11-23. **Status: source screen only; no confirmation set is frozen.** This note records a candidate source and an auditable selection protocol. It is not a license opinion, a dataset, or evidence that a clean held-out set is already available.

## What the repository has already seen

- The 13 Khronos glTF assets used by the AA, silhouette, decoder, and dynamic-LOD development screens are contaminated for a fresh confirmation test. Do not relabel any of them as held out.
- The 32-asset Thingi10K corpus has already informed several experiments. Its nominal test split is not an untouched confirmation set. The local metadata does not provide enough original creator attribution to treat the downloaded subset as redistribution-cleared.
- The local `third_party/models` directory contains nine Khronos samples, including assets already used by prior experiments. Presence in that directory does not establish that an asset is eligible for a fresh test.

## Freeze protocol

The bounded in-repository prior-use scan is reproducible with:

```powershell
python tools/mmtrain/audit_asset_reuse.py --asset third_party/models/Fox/Fox.glb --output tools/mmtrain/asset_reuse_audits/fox_20261123.json
python tools/mmtrain/audit_asset_reuse.py --asset third_party/models/DamagedHelmet/DamagedHelmet.glb --output tools/mmtrain/asset_reuse_audits/damaged_helmet_20261123.json
python tools/mmtrain/extract_static_gltf_geometry.py --input third_party/models/DamagedHelmet/DamagedHelmet.glb --output out/damaged-helmet-static.obj --receipt tools/mmtrain/asset_reuse_audits/damaged_helmet_geometry_extraction_20261123.json
python tools/mmtrain/audit_asset_reuse.py --asset third_party/models/shader_ball/shader_ball.obj --output tools/mmtrain/asset_reuse_audits/shader_ball_20261123.json
```

The receipt includes the scanned-file SHA-256 manifest and audit-script hash. Its recorded Git `HEAD` identifies the checkout at audit time, but the worktree was dirty; it is not the generating commit for earlier experiments.

1. Write down the target task, categories, inclusion/exclusion rules, and minimum geometry thresholds before rendering candidate outputs. Seek at least 20 eligible assets over at least five predeclared shape categories; report how many remain after screening.
2. Exclude every exact asset used in development and every duplicate, derivative, or near-duplicate of a development asset. Keep development, validation, and confirmation roles in a manifest; the confirmation labels and images must not influence method, hyperparameter, asset, view, or threshold choices.
3. For each candidate, capture the upstream repository commit and path; source and converted asset credits; license text/URL; whether redistribution is permitted under the intended release; the exact downloaded archive and extracted geometry SHA-256; importer version; source face/vertex counts; connected components; topology/attribute validity; and category assignment. Store receipts with the paper artifact.
4. Parse and validate all candidates using the same importer and geometry checks. Reject broken or unsupported assets before any method output is scored. Document exclusion counts and reasons. Do not silently replace difficult test assets after seeing results.
5. Split by asset, then freeze the manifest and protocol in a commit before one-time confirmation evaluation. Use multiple held-out views and camera paths per asset, and report paired asset-level uncertainty. Repeated views do not increase the number of independent assets.

## Current decision

The Khronos catalog is a promising lead, but the current browsing pass did not download candidates, verify geometry, archive every per-asset license receipt, or establish a five-category set of 20 eligible models. The one observed repository pointer does not replace file hashes. Fox is skinned and too small for the target simplification screen. DamagedHelmet has a useful face count but fails the strict topology gate and lacks byte-specific license provenance. Lucy is research-licensed but has exact prior-use matches. FlightHelmet and ShaderBall are development-only because of prior ManyMesh measurements. There is no clean two-asset comparison pair and no confirmation set. Continue using existing data only for development and feasibility screens. Do not call the nominal Thingi10K test split or any previously measured Khronos model held out until the freeze protocol is complete.
