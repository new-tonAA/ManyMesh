# Upscaler-aware cluster LOD: prior art and falsification plan

Updated 2026-11-23. **Status: candidate research question only.** The sources below are a literature map, not a novelty verdict. Search coverage is incomplete, and a failed search does not establish that a technique has never been published. Read the full papers and trace citations before writing a contribution claim.

An initial patent search found HTC's [EP4589546A1](https://patents.google.com/patent/EP4589546A1/en) and corresponding [US20250238997A1](https://patents.google.com/patent/US20250238997A1/en), *Method for generating an optimal tree for rendering or streaming a 3D model*. The published claims describe building an optimal tree from a complete model tree, per-node quality and view-dependent visibility values, with examples based on triangle/texel counts, projected area over viewer distance, and a triangle budget. This is adjacent to hierarchical LOD selection and budget allocation; the text inspected does not establish differentiable post-AA geometry optimization. This is a technical scope note, not a patentability, claim-scope, or freedom-to-operate opinion. Patent-family status, prosecution history, and additional patent coverage have not been systematically reviewed.

## Proposed question

Can an offline optimizer improve each level of an existing cluster DAG for the image produced after antialiasing or upscaling, while preserving the actual invariants: consistent shared boundaries (which may require progressive boundary representations rather than locked vertices), valid parent/child coverage, crack-free mixed cuts, and stable transitions? The loss could combine silhouette/coverage, normal or shading, and image error after a differentiable approximation to jittered accumulation and resolve. A stability term could penalize changes across adjacent LODs or frames.

The hypothesis is that optimizing a hierarchy for the final reconstructed image allocates geometry differently than optimizing an isolated mesh for one render scale. This has not been tested here. Do not assume an upscaler always repairs aliasing or can never recover missing detail: temporal reconstruction accumulates samples across frames and can lose thin details before enough history is available ([Epic's TSR documentation](https://dev.epicgames.com/documentation/unreal-engine/temporal-super-resolution-in-unreal-engine)). Measure the interaction with the actual pipeline. A differentiable approximation is not itself the result: the final method must also win when evaluated through real, non-differentiable AA/upscalers and account for all offline and runtime costs.

One possible motivation is that LOD selection and upscaling may use different pixel grids. The current BeamNG documentation describes LOD switch sizes in screen pixels and separately documents rendering below display resolution before temporal upscaling ([LOD selection](https://www.documentation.beamng.com/modding/levels/level_creation/section5/), [temporal upscaling](https://documentation.beamng.com/modding/postfx/upscaling/)). Those pages do **not** establish how its LOD threshold is scaled when render and display resolutions differ, or that this is an unresolved general engine problem. Treat the mismatch as a measurement question: record the LOD-selection viewport, render resolution, output resolution, jitter, and upscaler inputs for each tested pipeline before proposing a new metric.

The narrower candidate question is not whether image-space mesh fitting, silhouette-aware LOD, or stable transitions are new. Those are established. It is whether a mesh hierarchy optimized against a declared post-reconstruction operator has a reproducible quality-versus-cost advantage over ordinary simplification when the final images pass through that same operator, and whether a differentiable approximation predicts the ranking under real reconstruction. Test the actual spatial/temporal pipeline: an upscaler may suppress sampling artifacts, preserve or lose thin features, and amplify geometry changes or LOD switches. These are measurable hypotheses, not assumptions about what upscalers can or cannot repair. A “designed for upscalers” claim requires matched comparisons against native-resolution rendering, MSAA, SMAA, and the available upscaler, with render scale, output scale, jitter, history, and AA inputs fixed and reported.

Use two separate comparisons so the result answers both image quality and practical value. First match final face count and reconstruction settings to isolate geometry quality; report LDR-FLIP, PSNR, SSIM, silhouette/coverage error, and temporal quality on frozen camera paths. Then match complete frame time, including geometry processing, AA/upscaling, CPU selection/submission, and GPU work, to test whether the geometry method is worth its cost. Also report the equal-quality cost point when the measured curves support interpolation. Report each asset and paired asset-level uncertainty; do not pool correlated frames as independent samples. A tile-touch count is a proxy, not a substitute for real device timings or vendor counters.

## Closest prior art found

| Area | Verified precedent | Consequence for ManyMesh |
|---|---|---|
| Differentiable appearance optimization for simplification and LOD | Hasselgren et al., *Appearance-Driven Automatic 3D Model Simplification*, EGSR 2021. The full paper optimizes vertex positions and shading parameters against image references over randomized views and lighting, using off-the-shelf decimation to initialize reduced meshes. It includes resolution-specific prefiltering: MSAA is used during optimization to improve visibility gradients against a supersampled reference, while reported 1-spp outputs are rendered without AA. In its explicit multi-resolution vertex-placement example, each resolution gets optimized vertex positions, the topology stays fixed, and that example reports no triangle reduction. [Full paper](https://users.aalto.fi/~laines9/publications/hasselgren2021egsr_paper.pdf) · [NVIDIA project and code](https://research.nvidia.com/labs/rtr/publication/hasselgren2021diffmodeling/) · [nvdiffmodeling](https://github.com/NVlabs/nvdiffmodeling) | Differentiable image-space appearance optimization, target-scale prefiltering, MSAA-assisted silhouette gradients, simplification initialization, and multi-resolution vertex placement are established. “Optimize a mesh for its final resolution/AA” is not a gap by itself. A topology-distinct cluster-DAG method must identify a specific hierarchy constraint that changes the optimization problem and then show a benefit beyond this system.
| Learnable simplification of both vertices and topology | Potamias et al., *Neural Mesh Simplification*, CVPR 2022. A differentiable model learns point selection and candidate-triangle inclusion, producing simplified topology and reporting zero-shot generalization; its evaluation emphasizes surface/normal/topology metrics rather than post-upscaler image quality. [CVPR paper](https://openaccess.thecvf.com/content/CVPR2022/papers/Potamias_Neural_Mesh_Simplification_CVPR_2022_paper.pdf) | Learned topology reduction and differentiable mesh simplification are established. A ManyMesh method must address hierarchy-specific constraints and demonstrate gains over both deterministic and learnable baselines, not claim topology adaptation alone.
| Differentiable adaptive LOD construction with a visual criterion | Dou et al., *Differentiable Micro-Mesh Construction*, CVPR 2024. The μ-mesh framework jointly optimizes base geometry/displacements and supports per-base-triangle adaptive subdivision. Its visual-guided stopping criterion compares rasterized neighboring subdivision levels, while constraining adjacent subdivision levels to differ by at most one to maintain watertightness. [CVPR paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Dou_Differentiable_Micro-Mesh_Construction_CVPR_2024_paper.pdf) | Differentiable geometry construction, image-guided adaptive LOD, and cross-level watertightness constraints already coexist in a specialized displacement-mesh representation. This is a close method precedent; read it closely and compare representation, objective, and hierarchy invariants.
| Joint differentiable mesh geometry and appearance refinement | Choi et al., *LTM: Lightweight Textured Mesh Extraction and Refinement of Large Unbounded Scenes for Efficient Storage and Real-time Rendering*, CVPR 2024. [CVPR paper](https://openaccess.thecvf.com/content/CVPR2024/papers/Choi_LTM_Lightweight_Textured_Mesh_Extraction_and_Refinement_of_Large_Unbounded_CVPR_2024_paper.pdf) | Joint image-space vertex/appearance optimization on simplified meshes is established. Its source is reconstructed NeRF geometry, not a pre-existing cluster LOD DAG, but the objective and deformation baselines overlap directly.

[NeurIPS paper page](https://papers.nips.cc/paper_files/paper/2024/hash/1651f1ea5ee6213e301a89f222f3fec7-Abstract-Conference.html) | Gradient-based mesh topology adaptation from image observations is established in reconstruction. This is not a simplification hierarchy, but it further narrows claims about differentiable mesh topology optimization.
| Image-driven simplification | Lindstrom and Turk, *Image-Driven Simplification*, ACM TOG 2000. | Photorealistic simplification in the image domain | Rosenthal et al., *Progressive Photorealistic Simplification*, SIGGRAPH 2026. [Author page](https://adirosenthal540.github.io/Progressive_Photorealistic_Simplification/) · [arXiv record](https://arxiv.org/abs/2605.10409) | This is adjacent visual-simplification work, not a mesh simplifier or LOD baseline. It reinforces that “photorealistic simplification” is broad terminology; do not use that phrase as a differentiable-geometry contribution. The 10-page paper was not available in this review, so no detailed method comparison is claimed.
| Neural appearance prefiltering across levels of detail | Weier et al., *Neural Prefiltering for Correlation-Aware Levels of Detail*, SIGGRAPH 2023 / ACM TOG 42(4), 2023. The full paper replaces per-voxel light transport with two learned components on a sparse multilevel voxel grid: an appearance network for intra-voxel throughput and a visibility network that preserves correlations across voxel boundaries. It spans voxel resolutions from 512^3 to 8^3 and reports 70 to 95 percent storage savings relative to the classic source representation. [Full author PDF](https://weiphil.s3.eu-central-1.amazonaws.com/neural_lod.pdf); [ACM DOI](https://doi.org/10.1145/3592443) | Neural prefiltering that preserves appearance and correlated visibility across LODs is established. | Adaptive triangle topology with image supervision and scale-aware filtering | Tang et al., *T²-Splat: Adaptive Topology Mesh Splatting with Texture Residuals*, arXiv preprint posted 4 November 2026. The full paper and supplement describe safe restricted-Delaunay initialization, QEM edge collapses, gradient-driven vertex splits, differentiable image supervision, topology checks, optimizer-state transfer, and per-face residual mip textures. Its target is mesh-based novel-view reconstruction from captured scenes; it does not describe a reusable multilevel triangle-mesh cluster DAG or legal mixed cuts. The paper evaluates rendered images and scale-adaptive texture filtering, but does not report an MSAA/SMAA or real temporal-upscaler comparison. [Full preprint and supplement](https://arxiv.org/html/2611.06974) | This is a close, current precedent for differentiable triangle-topology adaptation plus scale-aware appearance filtering, so that combination is occupied. The possible difference is a constrained pre-existing DAG with shared interfaces and mixed-cut validity, evaluated after real reconstruction operators at matched complete cost. That is a narrow representation-and-evidence distinction, not a verified novelty claim.
| Learned reconstruction and mobile neural rendering | Arm documents Neural Super Sampling on Mali G2-Ultra NX, which combines dedicated neural accelerators with low-resolution inputs, temporal history, and integrated AA. [Arm overview](https://newsroom.arm.com/blog/arm-mali-g2-ultra-nx-ai-native-mobile-graphics) · [Product capabilities](https://support.arm.com/compute-ip/mali-g2-ultra) | A small image CNN losing to MSAA does not establish that neural reconstruction is generally weak. NSS is a relevant vendor baseline only on supported hardware; mobile claims require a real device and a qualified cost-matched comparison.
| Meshlet/geometry compression | Kuth et al., *Towards Practical Meshlet Compression*, report about 5.9 bits/triangle for the topology/index stream with their GTS-Reuse variant; this is not a total geometry-file rate and should not be compared directly with a codec that includes vertex attributes or other metadata. AMD DGF is a separate hardware-friendly meshlet format; its compression and decode results use their own accounting and hardware setup. [Paper](https://gpuopen.com/download/Towards_Practical_Meshlet_Compression_paper.pdf) · [DGF](https://gpuopen.com/learn/amd-dgf-an-open-geometry-compression-standard/) | “Compress cluster geometry” is occupied and byte claims need a named codec, full-stream accounting, and equal decode costs.
| Mobile Nanite engineering | Arm's Mori demo used a modified Unreal Engine 5.5.2 desktop renderer on a Vivo X200 Pro with Mali-G925. Arm reports 15.75 FPS in the initial scene, 27.33 FPS with WPO disabled, and up to 35.75 FPS with masked materials disabled; those material changes also affect appearance. [Arm report](https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/mori-to-nanite-billions-of-triangles-on-mobile) | This establishes an engineering deployment, not a new ManyMesh result or a quality-matched performance claim. Do not claim Nanite-like geometry on phones as the contribution; compare algorithms and full costs on actual devices.

The candidate must now be stated narrowly: optimize vertex positions across topology-distinct nodes of an existing triangle-mesh cluster DAG against a measured post-reconstruction objective, and demonstrate a benefit that survives real AA/upscalers at matched complete cost. Even this phrasing is not a novelty claim. Hasselgren et al. already optimize appearance at a selected scale and use MSAA during training; T²-Splat already joins adaptive triangle topology, image supervision, and scale-adaptive filtering. Potamias et al. learn simplification topology; Dou et al. combine differentiable geometry construction, image-guided adaptive subdivision, and watertightness constraints; Choi et al. optimize simplified mesh geometry and appearance from image-space losses; Liang et al. jointly simplify mesh and shader; Zhang and Peng cover fixed-budget foveated selection on large hierarchical meshes; HLoD jointly optimizes a screen-space Gaussian hierarchy; V3DG performs differentiable local fitting at each cluster-LOD level and selects clusters by screen-space footprint; Weier et al. and Zhou et al. perform appearance-aware LOD filtering/aggregation at pixel scale; Siemers explores sampling-aware LOD plus filtering for 3DGS; Ladeuil et al. report coupled internal and boundary Progressive Meshes for cluster interfaces; Yoon et al. already use adjacent-cluster dependencies for crack-free CHPM simplification and describe popping from dependency-forced splits; Nanite already uses subpixel error with TAA. Therefore shared-boundary preservation, legal mixed cuts, hierarchy optimization, cluster-wise differentiable fitting, image-space fitting, and transition stability cannot be presented as new in isolation. The possible contribution is an experimentally validated algorithmic improvement over those systems in a specific constrained triangle-mesh cluster DAG, under real post-reconstruction quality and matched complete cost. That distinction is unproven and has substantial novelty risk. Before making a claim, read the full clustered-HLOD, mesh/shader LOD, and VR-transition papers; trace citations and patents; search recent proceedings and production systems; and validate that a differentiable surrogate predicts rankings under real pipelines. The V3DG full paper and supplementary sections and Quick-VDR full paper have now been read; HLoD remains an abstract-level review because the full-text endpoint was inaccessible. This remains a bounded first-pass review rather than a systematic survey.

## Additional direct mesh-hierarchy precedent

Zhang and Chen, *Constructing and Rendering of Multiresolution Representation for Massive Meshes with GPU and Mesh Layout*, *Journal of Software* 8(8), 2013, pp. 1968–1975, DOI [10.4304/jsw.8.8.1968-1975](https://doi.org/10.4304/jsw.8.8.1968-1975), is a direct mesh-hierarchy precedent that should be included in any representation comparison. The [full paper](https://www.jsoftware.us/vol8/jsw0808-20.pdf) describes a graph-partitioned cluster hierarchy; each cluster has a progressive mesh and a vertex hierarchy for fine-grained local refinement. Coarse cluster selection and fine vertex refinement are view-dependent, and GPU parallel streaming passes update the active vertex frontier and index buffer. GPU dependency rules constrain legal splits/collapses and prevent foldovers.

Its 2009-era evaluation uses a GeForce 9800 GTX+ and one-pixel projected error. For Dragon, Thai Statue, and Lucy, it reports 12–41 ms rendering for 307,216–529,960 triangles, and 39.2–161.8 minutes of preprocessing. This is historical evidence, not a modern matched-cost baseline. It establishes that coarse cluster selection plus fine progressive vertex refinement, including GPU-parallel updates, is not a new representation idea. The paper does not describe differentiable image optimization after AA/upscaling, temporal accumulation, or optimization of node geometry against reconstructed images. Those differences delimit the research question but do not establish novelty.

## Direct prior art on subjective quality and perceptual LOD

Nguyen, Ly, and Huong, *Subjective Quality Assessment of Dynamic 3D Meshes in Virtual Reality Environment* (IEICE Transactions on Information and Systems, advance online 2026), is directly relevant to quality claims. Their study used eight animated meshes, eight LoDs, five viewing distances, and 320 stimuli in a Meta Quest 2 VR setup. Twenty-four participants took part, with each stimulus rated by 20 participants using a five-grade DSIS impairment scale. In that protocol, objective-metric correlation with MOS was modest: PLCC was 0.58 for PSNR, 0.49 for SSIM, 0.48 for MS-SSIM, 0.26 for NIQE, 0.19 for PIQE, 0.33 for Hausdorff and geometric RMSE, 0.49 for Chamfer, and 0.58 for screen-space error. These findings do not invalidate those metrics; they show that they are not substitutes for user ratings in every content, viewing, or presentation setting. [Full open-access paper](https://www.jstage.jst.go.jp/article/transinf/advpub/0/advpub_2026PCP0007/_pdf) · [DOI record](https://doi.org/10.1587/transinf.2026PCP0007).

The same paper trains a Random Forest QoE predictor and reports RMSE 0.19, PLCC 0.98, SROCC 0.97, and KROCC 0.88. However, its 320 stimuli are randomly split 80/20 and the split is repeated ten times. Because the same eight meshes contribute stimuli to both partitions, this protocol does not establish generalization to unseen assets; that is an inference from the reported split procedure. Treat its predictor as a useful baseline or hypothesis, not a validated ManyMesh metric. A subsequent Web3D '26 paper, *Improve Rendering of Dynamic 3D Meshes in WebVR Environments with QoE-aware Level of Detail Adaptation*, applies a QoE predictor to LOD allocation under a GPU-memory budget on Meta Quest 2. This makes perceptual/resource-aware LOD allocation prior art. The ACM record and indexed text were available, but the full paper was not accessible in this review, so its detailed method and claims still need full-text verification. [ACM record](https://doi.org/10.1145/3822516.3834879).

These works do not describe optimizing triangle-mesh cluster-DAG geometry against quality measured after real AA or upscaling. That difference is only a candidate question, not a novelty finding. For ManyMesh, report technical metrics as separate measurements; reserve “perceptual” or user-preference claims for a predeclared subjective study or a predictor shown to generalize across held-out assets and conditions. In every learned model comparison, split by source asset so that all views, LODs, and camera paths from a mesh remain in one partition. Report per-asset outcomes and uncertainty resampled over assets, not over correlated frames or views.

### Advance criterion

Advance only if the frozen nvdiffmodeling baseline or current placement produces a repeatable held-out quality improvement at matched final face count, and the improvement survives both AA settings without topology/boundary regressions. This is a feasibility signal only: it does not establish novelty against Neural Mesh Simplification, differentiable μ-mesh construction, LTM, or the cluster-HLOD boundary methods. Set practical-effect margins from repeated baseline variance before scoring. If the result is null or view-specific, stop the differentiable LOD branch before building a custom pipeline.

## Constrained DAG experiment, only if the placement baseline passes

1. **Freeze the structure for the first placement test.** Keep cluster membership and boundary vertices fixed initially, and optimize allowed interior positions at each DAG level. This is a control that isolates vertex placement, not a proposed boundary solution: HLOD ASAP reports that locked boundaries can waste faces and lose features. Verify parent/child coverage, all legal mixed cuts, cracks, winding, manifoldness, UV/material seams, and displacement bounds. If the placement test passes, compare against progressive boundary treatment, including HLOD ASAP's internal/boundary Progressive Mesh representation; do not claim locked-boundary quality as state of the art. Fixed topology is a first test, while topology changes remain a separate harder study.
2. **Match use scale.** Sample held-out camera paths and projected sizes for each level rather than optimizing every level at one arbitrary resolution. Split views/assets before fitting. Prevent reference-image leakage into runtime selection.
3. **Specify the reconstruction operator.** First use a differentiable surrogate for subpixel jitter, sample accumulation, and resolve. Record all approximations. Then render the frozen optimized meshes through actual MSAA/SMAA and available spatial/temporal upscalers. Filament provides FSR1 through fixed-scale dynamic resolution and a separate beta TAA-upscaling path; its options document that TAA upscaling disables dynamic resolution, while FSR1 expects an antialiased input. Treat them as separate arms, and report the exact render scale and AA mode. The current `mm_bench` source compiled and linked against pre-existing build outputs, but Windows Application Control blocked both the full dependency regeneration and executable launch. These switches remain unexercised and no FSR1/TAA-upscaling result exists; see the [build record](tools/mmtrain/RENDER_HARNESS_BUILD_20261123.md). The surrogate must predict ranking or benefit on held-out real-pipeline renders to remain useful. See [`Options.h`](filament/include/filament/Options.h) and [`Renderer.cpp`](filament/src/details/Renderer.cpp).
4. **Compare at matched budgets.** Include QEM, current placement, meshoptimizer cluster LOD, faithful nvdiffmodeling, and Neural Mesh Simplification where a fair replication is available. Compare the boundary/cross-level representation with Quick-VDR and modern clustered-HLOD methods, including HLOD ASAP; if its full implementation or method details are unavailable, state the limitation and implement a clearly labeled boundary-PM comparator rather than treating locked boundaries as an adequate substitute. Include μ-mesh visual-guided adaptive LOD and LTM's joint geometry/appearance refinement as close objective/representation references, or explain why they are not comparable controls. Match final faces and separately report bytes, offline optimization time, load/decode cost, memory, selector cost, GPU time, and complete-frame time. Compare AA/upscalers under equal complete frame time, not only equal image resolution.
5. **Measure image and temporal quality.** Report LDR-FLIP, silhouette/coverage, PSNR, SSIM, surface and normal error, topology, and a validated temporal metric over moving paths. A temporal frame-difference diagnostic is not a perceptual score. If the claim uses “perceptual,” add a powered user study or use a validated perceptual model with the required protocol.
6. **Hold out assets.** The existing 32-asset corpus has informed earlier ManyMesh experiments, so do not assume its nominal 8-asset test split is uncontaminated. Audit prior access by asset hash before assigning any test role. It can still serve as development data; publication claims require a fresh, independently licensed, category-balanced confirmation set (target at least 20 assets across five or more categories) that is sealed until parameters and exclusions are frozen.

### Kill conditions

Stop if the candidate loses to a matched deterministic baseline, if the result depends on training views/assets, if the differentiable surrogate does not predict the real upscaler ranking, if boundary/topology constraints fail, or if preprocessing and memory costs erase the runtime benefit. Do not change `.mmb`, the production renderer API, or the public library for this research question before the held-out gate passes.

## Fallback directions

- **Measured tile-based cost model:** potentially useful if a physical tile-based phone is available. [Meta's tiled-rendering guide](https://developers.meta.com/vr/documentation/unreal/gpu-tiled/) and [Arm's profiling guide](https://developer.arm.com/community/arm-community-blogs/b/mobile-graphics-and-gaming-blog/posts/finding-and-fixing-hidden-performance-problems-in-mobile-games-with-arm-performance-studio) describe architecture-specific tiling/binning costs. A screen-space tile-touch count is only a proxy; fit and validate against real vendor counters/stage timings, including clipping, triangle shape, overdraw and MSAA. Do not turn a qualitative architecture fact into a universal “triangles binned” cost claim.
- **Rate-aware DAG construction:** only reopen with a complete byte-level comparator against meshoptimizer, Draco, Kuth et al., and DGF, including topology, attributes, headers, shared decoder weights, load/decode time and peak memory.
- **Temporal transitions:** geomorphing and perceptual LOD-switch modeling already exist. Reopen only for a measured residual artifact and a stronger baseline comparison.
